# 安全与数据说明

## 数据会流向哪里

LLM_in_Excel 是本机 Excel 加载项，但模型推理通常发生在所选 CLI 的服务端，并非完全离线。

- 首轮或上下文变化时，会把工作簿内容作为上下文交给所选的 Claude Code / Codex CLI：目标所在的工作表和当前工作表按单元格全部列出（公式附上计算结果），其他工作表只发前几行预览；隐藏的工作表也会发送。只选一列也可能发送整张表；很大的表按目标附近的行截取。批注、图表和数据透视表不会发送。
- 只有主动附上的参考文件才会发送。图片和 PDF 附件会先写入系统临时目录，请求结束时清理。
- 对话历史、输入草稿和目标位置（工作表 ID、区域地址和发送时的单元格内容）保存在面板的本地存储中，不写进工作簿。应用后用于撤销的记录只保存在当前面板的内存里。CLI 自身也可能在其会话目录中保存对话，具体受 CLI 设置约束。
- 本项目不要求在仓库中配置 API key，也不提供云端代理。

## 本机边界

服务只监听 `127.0.0.1`，默认端口 `8397`。macOS 注册用户级 launchd 服务，数据放在 `~/.llm_in_excel/`；Windows 使用当前用户的启动快捷方式，数据位于 `%LOCALAPPDATA%\LLM_in_Excel`。不要把该端口转发或暴露到公网；这个服务不是面向多用户的身份认证网关。

macOS 安装时如果发现 LLM_in_Word 或 LLM_in_PowerPoint 已信任的本机证书，会把证书和私钥复制到 `~/.llm_in_excel/cert`（私钥权限 600）并沿用，不再新建和信任新的证书。证书只对 `localhost` / `127.0.0.1` 有效。卸载 Excel 版时不会删除钥匙串里的证书，因为 Word 版或 PowerPoint 版可能还在使用。

面板对工作簿只写入单元格内容，不运行宏。Claude 纯文本请求不启用工具，带附件的请求只启用 Read；Codex 使用只读沙箱并禁止交互式批准，但仍可能加载本机配置中的工具。账户与数据处理规则由对应 CLI 及其服务提供方管理。

## 报告问题

请不要在公开 Issue 中粘贴密钥、真实工作簿或带凭证的日志。若仓库已启用 GitHub Private Vulnerability Reporting，可使用 Security 页面的 “Report a vulnerability”；否则请通过已有的私有渠道联系维护者。另见[仓库安全说明](../SECURITY.md)。

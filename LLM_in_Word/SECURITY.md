# 安全与数据说明

## 数据会流向哪里

LLM_in_Word 是本机 Word 加载项，但模型推理通常发生在选用 CLI 的服务端，并非完全离线。

- 首轮或上下文变化时，会将文档正文作为上下文交给所选 Claude Code / Codex CLI。只选择一段文字仍可能发送全文；超长文档按目标附近截取。
- 附件会随请求提供给 CLI；图片/PDF 会先写入系统临时目录，请求收尾时清理。
- 对话历史和输入草稿保存在面板的本地存储中。CLI 自身也可能在其会话目录中持久化对话，具体受 CLI 设置约束。
- 本项目不要求在仓库中配置 API key，不提供自建云端代理。

## 本机边界

服务监听 `127.0.0.1`，默认端口 `8377`。安装脚本创建 localhost HTTPS 证书，macOS 注册用户级 launchd 服务并将数据放在 `~/.llm_in_word/`（旧版沿用 `~/.word_edit/`）；Windows 使用当前用户的启动快捷方式，数据位于 `%LOCALAPPDATA%\LLM_in_Word`。不要把该端口转发或暴露到公网；当前服务不是面向多用户部署的身份认证网关。

Claude 纯文本请求不启用工具，附件请求只启用 Read；Codex 使用只读沙箱并禁止交互式批准，仍可能加载本机配置中的工具。账户与数据处理规则由对应 CLI 及其服务提供方管理。

## 报告问题

请不要在公开 Issue 中粘贴密钥、真实文档或带凭证的日志。若仓库已启用 GitHub Private Vulnerability Reporting，可使用 Security 页面的 “Report a vulnerability”；否则请通过已有私有协作渠道联系维护者。另见[仓库安全说明](../SECURITY.md)。

报告应包含版本、操作系统、合成复现步骤、影响及已去除敏感信息的日志。`.gitignore` 只是防误提交措施，不能替代提交前审查。
